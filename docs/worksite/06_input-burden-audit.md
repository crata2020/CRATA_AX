## 0. 한눈에 보기

1. **63개 화면 중 매일 손이 가는 기록 화면은 6개입니다.** 현장 등록, 생산 실적, 출하 등록, 설비 현황판, 설비 오늘 점검, 업무 진행 기록입니다. 나머지는 보기 12개, 버튼 한 번 누르기 19개, 짧은 입력 9개, 폼 23개이고, 폼은 대부분 '가끔' 또는 '처음 한 번'입니다([3장](#3-숫자로-본-결과)).
2. **부담이 큰 곳은 설비 두 화면과 생산 실적입니다.** 설비 현황판은 52대 × 2교대라 하루 최대 104번, 오늘 점검은 하루 약 52번, 생산 실적은 하루 약 24건입니다. 셋 다 TR 1단계에서는 메뉴에서 뺐고, 다시 켜기 전에 **"모두 가동·모두 이상 없음" 묶음 버튼**과 **연동**을 먼저 붙입니다([4장](#4-부담이-큰-화면과-해결-방향)).
3. **사이트에 입력 화면이 아예 없는 데이터가 24종입니다**(작업지시, 수주, 검사, LOT 연결, KPI 등). 이것을 사람에게 새로 입력시키면 운영이 곧 일이 됩니다. 이 데이터는 **ERP·엑셀 가져오기, 녹음·메일 연동, AI 읽기, 다른 기록에서 자동 계산**으로만 들어오게 합니다([5장](#5-사람이-입력하면-안-되는-데이터)).
4. **승인·확인은 이미 대부분 버튼 한 번이었지만 화면 5곳에 흩어져 있었습니다.** 이번에 홈 **'승인 대기'** 카드 하나로 모았습니다. 검토 승인, 회의 액션→업무, 회의 분류 확인, 결정 확정, 현장 등록 배정, 작성 규칙 반영을 홈에서 한 번 눌러 끝냅니다([6.3](#63-승인-대기-카드)).
5. **TR은 '1단계'로 시작합니다.** 메뉴는 홈 + 7개(내 업무, 검토함, 회의, 분류 확인, 현장 등록, 품질 현황, 클레임·8D)만 보입니다. 모듈과 데이터는 다 켜 둔 채 메뉴·홈만 줄여서, 관리자가 **회사 설정 › 모듈 › 도입 단계**에서 버튼 한 번으로 '전체'로 넓힙니다([6장](#6-tr-1단계-구성-이번에-만든-것)).
6. **회사 관리자가 하는 운영 일은 세 가지로 줄었습니다.** 구성원 초대·퇴사 처리, 도입 단계 넓히기, 가끔 회사 설정 변경 요청입니다. 사업 구조·용어·양식·배분 규칙·추천 담당은 CRATA가 진단(Company DNA) 때 넣습니다.

## 1. 점검 기준

| 항목 | 값 | 뜻 |
|---|---|---|
| **종류** | 보기 | 입력 없음(목록·현황·검색) |
| | 누르기 | 버튼 한 번으로 끝남(승인, 확인, 상태 넘기기) |
| | 짧은 입력 | 한 줄 글 또는 선택 몇 개 |
| | 폼 | 필드 5개 이상을 채움 |
| **부담** | 상 | 매일 여러 번 × 여러 사람, 또는 필드가 많은 입력을 매일 |
| | 중 | 매일 조금 또는 매주 폼 |
| | 하 | 가끔, 한 번 누르기, 처음 한 번 |
| | — | 입력 없음 |
| **TR 1단계** | 보임 | 1단계 메뉴에 있음(홈은 늘 보임) |
| | 링크 | 상세 화면. 원래 메뉴가 없고 목록·알림·홈 카드에서 열림 |
| | 숨김 | 1단계 메뉴에서 뺐음. 지우지 않았고 링크·주소로는 열림 |
| | 관리자 | 관리 메뉴(소유자·관리자에게 늘 보임) |
| | 메뉴 밖 | 상단 바·프로필에서 엶(단계와 상관없음) |
| | TR 없음 | CRATA(교육·컨설팅) 전용 화면 |

**자동으로 바꿀 방법**은 다섯 가지로 나눴습니다.
- **AI 초안:** AI가 채우고 사람은 확인만 합니다.
- **회사 규칙:** 추천 담당, 배분 규칙, 자동 분류처럼 진단 때 정한 규칙으로 채웁니다.
- **연동:** ERP, 그룹웨어, 메일, 녹음기(Plaud·클로바), 설비 신호에서 가져옵니다.
- **기본값·기억:** 지난 값, 직책별 기본 역할 같은 값으로 채웁니다.
- **묶음:** 바뀐 것만 누르고 나머지는 한 번에 처리합니다.

```ts
},
```

- **메뉴만 줄이고 모듈은 끄지 않습니다.** 품질 모듈이 기준정보·문서·업무 모듈을 쓰는 것처럼 모듈끼리 이어져 있어서, 모듈을 끄면 다른 화면이 깨집니다. 그래서 1단계는 메뉴와 홈만 거릅니다. 숨긴 화면도 알림·홈 카드의 링크로는 열립니다.
- **넓히기는 버튼 한 번입니다.** 회사 설정 › 모듈 › **도입 단계**에서 '전체'를 누르면 메뉴 8개 → 35개가 바로 보입니다. 되돌리기도 한 번입니다(`rpc:set_rollout_stage`, 감사 기록 남김).
- 1단계 동안 소유자·관리자 홈 맨 아래에 "지금은 도입 1단계예요 … 한 번에 넓힐 수 있어요" 한 줄이 보입니다.
- 현장 등록 화면의 '담당 정하기' 서랍도 같은 `routing` 규칙으로 추천 담당을 채웁니다(한 곳에서 고치면 둘 다 바뀜).

### 6.2 역할별 1단계 홈

| 역할 | 1단계 홈(인사 다음 순서) | 이유 |
|---|---|---|
| 대표 | 승인 대기 · 품질 PPM · 클레임·8D | 대표는 결정 확정·검토가 주 일. 품질 비전(Single PPM) 확인 |
| 공장장 | 승인 대기 · 오늘 현장 등록 · 클레임·8D | 현장 배정·검토·회의 확인이 모두 공장장에게 모임 |
| 품질보증 | 클레임·8D · 승인 대기 · 품질 PPM | 자기 일(클레임)을 먼저. 승인할 일은 적음 |
| 영업·생산 | 내 업무 · 승인 대기 | 승인할 일이 적음 |
| 총무·구매·경리 | 내 업무 · 승인 대기 | 아차사고·기타 현장 등록이 배정되어 옴 |
| 개발 | 내 업무 · 수정 요청 받은 제출 | 검토 권한 없음 |
| 생산 작업자(모바일) | 현장 등록 큰 버튼 4개 · 내 업무 | 탭 두 번 + 한 줄이면 끝 |

평소(전체 단계) 홈은 위젯이 7~8개였습니다. 1단계는 2~3개입니다.

### 6.3 승인 대기 카드

AI나 회사 규칙이 담당·분류를 미리 채우고, 사람은 맞으면 한 번 누릅니다. **같은 건이 두 사람 할 일로 보이지 않게** 각 건은 한 사람 홈에만 나옵니다.

| 종류 | 누구 홈에 | 미리 채워진 것 | 한 번 누르면 | 다르면 |
|---|---|---|---|---|
| 검토 | 지정 검토자 | 제출 내용(AI 연결 제출 포함) | **승인** → 업무 완료, 담당에게 알림 | '수정 요청' → 검토함(코멘트 필요) |
| 현장 배정 | 배정 역할(TR: 공장장) | 종류별 추천 담당 | **배정**(내가 담당이면 '내가 맡기') → 담당에게 알림 | '다른 담당' → 현장 기록 서랍 |
| 회의 액션 | 회의 프로젝트의 검토자 | 제목, 추천 담당, 기한 | **업무로 만들기** → 담당에게 업무 | '고치기' → 분류 확인 |
| 회의 결정 | 결정 역할(예: 대표이사) | 결정 문장 | **확정** | '고치기' |
| 회의 분류 | 회의 프로젝트의 검토자 | AI 분류(사업 › 프로젝트, 확신 %) | **분류 맞아요** | '고치기'. AI가 분류 못 한 구간은 '직접 골라야 해요' 줄로 따로 |
| 작성 규칙 | 지정 승인자 | 같은 수정이 N번 → 규칙 문장 | **반영** 또는 **이번만** | '고치기' → 작성 규칙 |

- 한 번에 4건만 보이고, 처리하면 다음 건이 올라옵니다. 위쪽 칩(검토 4, 현장 배정 2 …)을 누르면 종류별 화면으로 갑니다.
- **나중에**를 누르면 그 건은 오늘 하루 숨고 내일 다시 보입니다(이 브라우저에만 저장).
- 예시 데이터 기준 공장장 홈 14건(검토 4 · 현장 배정 2 · 회의 액션 2 · 결정 1 · 분류 3 · 규칙 2) + 직접 골라야 하는 1건, 대표 홈 5건입니다.
- 검증: 단위 테스트가 두 회사 10개 역할로 카드의 모든 버튼을 실제로 눌러 0건이 되는지 확인합니다([`tests/unit/rollout.test.ts`](../../apps/worksite/tests/unit/rollout.test.ts)).

## 7. 넓히는 순서 (제안)

03 문서 8.2절의 1차 파일럿(8~10주)은 품질·현장 등록·설비·안전보건 전체를 담습니다. 이번 1단계는 그 **앞 2~4주**입니다. 아래 조건이 차면 하나씩 넓힙니다.

| 순서 | 열 것 | 먼저 갖출 것 | 넓히는 조건(예시) |
|---:|---|---|---|
| 1 | (지금) 1단계 7개 화면 | 녹음 연동, 추천 담당 규칙 확인 | — |
| 2 | 설비 현황판·설비 점검 | '모두 가동'·'전부 이상 없음' 묶음 버튼 | 현장 등록이 주 20건 이상, 승인 대기를 하루 안에 처리 |
| 3 | 안전보건(위험성평가·반기 점검) | 법령 체크리스트·작년 평가 가져오기 | 반기 점검 시기 |
| 4 | 메일 제안·문서·작성 규칙 메뉴 | 메일 연동, 드라이브 폴더 연동 | 클레임 8D 1건 이상을 사이트에서 제출 |
| 5 | 수주·생산·자재·LOT | ERP·엑셀 가져오기 | 2차 파일럿 |
| 6 | ARA(복지) | 동의 안내, 개인 영역 설명회 | 업무 화면이 자리 잡은 뒤 |

지금 코드에는 '1단계'와 '전체' 두 단계만 있습니다. 위처럼 중간 단계가 필요해지면 `rollout`에 단계를 더 두는 방식으로 넓힙니다(설정만 바뀌고 화면 코드는 그대로).

## 8. 남은 한계

- **'승인'은 내용을 열지 않고도 누를 수 있습니다.** 제목을 누르면 내용이 열리지만, 금액이 크거나 L2(민감) 건은 한 번 누르기 대신 내용 확인을 꼭 거치게 할지 회사와 정해야 합니다.
- **추천 담당 규칙은 가설입니다.** 종류별 담당(불량 → 품질, 설비 → 공장장, 아차사고·기타 → 총무)은 진단 때 TR의 실제 규칙으로 바꿉니다.
- **'나중에'는 이 브라우저에만 저장됩니다.** 다른 기기에서는 다시 보입니다.
- **수정 요청은 코멘트가 필요해서 한 번 누르기가 아닙니다.** AI 코멘트 초안은 2단계입니다.
- **회의 자동 등록(녹음 연동)은 아직 뼈대에 없습니다.** 5장 주의를 보세요.
- 빈도 숫자는 예시 데이터에서 셌습니다. 실제 하루 건수는 진단 때 다시 셉니다.
